INTRUST · AGENTIC AI

InTrust already captures demand at the moment of intent — in chat, on the storefront, in the merchant's daily operations. Today that conversation ends with information. The opportunity is to let it end with a result: an item added, an order explained, a merchant question answered from their own data, a cart prepared for a secure checkout.

Today — the assistant answers
  • Answers a question and stops at information.
  • Explains steps the user must then perform manually.
  • Hands the user off to a sequence of screens.
  • Every journey restarts from the beginning.
Proposed — the agent completes
  • Understands intent from text, image, voice or a mix.
  • Assembles only the context the signed-in user is allowed to see.
  • Selects an approved capability from a fixed registry.
  • Completes the request through the workflows InTrust already runs.

Fewer steps to the same outcome

Natural language replaces multi-screen navigation, so demand is acted on while it is still fresh.

The trust model stays intact

Authentication, permissions and business rules remain the authority. The agent operates inside them.

One foundation, two audiences

The same intelligence layer serves customers and merchants through different permissions.

Scope noteNothing in this document should be read as delivered functionality. It describes a proposed capability, and the design principles it would follow if built.

User-scoped

Every read and action is limited to the caller.

Capability-bounded

Only reviewed actions from a fixed registry.

Server-authoritative

The platform decides, not the model.

Observable

Requests, selections and outcomes are traceable.

Reversible

Any capability can be switched off independently.

Questions we would baseline with InTrust

Which customer and merchant journeys matter most today?
Which events already measure completion, and what are their current values?
Which actions feel safe enough to execute without a confirmation step?
What support and merchant feedback themes should the agent absorb first?

Commitments this proposal makes

No new source of truth, and no duplicate commerce backend.
No change to how customers authenticate or check out.
No capability enabled until it has been reviewed and approved.
No silent state changes — every outcome is visible to the user.
Not in scopeNo new app to install, no data migration and no change to how InTrust customers pay — and no decision needed today beyond agreeing the shape of the first phase.
