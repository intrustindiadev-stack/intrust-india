What this is

A conversational action layer over the existing InTrust platform.
Permission-aware by design — every action is scoped to the signed-in user or merchant.
Built on a fixed registry of approved capabilities, each mapped to existing logic.
Observable — requests, selections and outcomes can be traced and reviewed.

What this is not

Not a rebuild of the platform, the catalogue or the order journey.
Not a second source of truth — no duplicate commerce backend.
Not unrestricted access to data, tables or internal APIs.
Not a payment or financial actor — checkout and payments remain untouched.

Where it fits in InTrust today

Alongside the existing customer app and storefront conversation.
Inside the merchant panel as an operational assistant.
On the communication channels InTrust already uses with users.
Behind the same sign-in the user already trusts.

Decisions this proposal asks for

Approve the capability list for Phase 01 and Phase 02.
Confirm which low-risk actions execute without confirmation.
Agree the baseline metrics that define success.
Agree the review and audit rhythm for agent decisions.
